# LEDControl -- dependencies for an Intel Mac (tested: 2020 MacBook Air,
# i3-1000NG4, macOS 15.8, system Python 3.9.6).
#
# Use this INSTEAD of requirements.txt on such a machine:
#   python3 -m venv venv && source venv/bin/activate
#   pip install -r requirements-intel-mac.txt
#   (no Homebrew, no PyAudio: core/mic.py records through sounddevice)
#
# Why a separate file: requirements.txt is pinned for Apple-silicon Python 3.14.
# PyTorch stopped building Intel-Mac wheels after 2.2.2, and torch 2.2.x needs
# NumPy 1.x, while OpenCV 5 needs NumPy 2. So this machine runs the older set:
# torch 2.2.2 / numpy 1.26.4 / OpenCV 4.10.
#
# Never compile cryptography from source here: google-genai -> google-auth pulls
# it in, the newest release has no prebuilt wheel for Intel Mac + Python 3.9,
# and the fallback source build needs Rust and OpenSSL headers (it failed on the
# 2020 Air). With this line pip walks back to the newest version that has a wheel.
--only-binary=cryptography
cryptography==48.0.1   # what pip landed on, on the 2020 Air (the newest, 50.x, has no wheel there)

# PINNED = installed and exercised by tools/bench.py (hand tracking, Whisper,
# both together). Not yet exercised by the real apps.
mediapipe==0.10.14
numpy==1.26.4
openai-whisper==20250625
opencv-contrib-python==4.10.0.84
pygame-ce==2.5.6
soundfile==0.13.1
sounddevice   # microphone input; also a mediapipe dependency. Unpinned: version not recorded.
SpeechRecognition==3.17.0
torch==2.2.2

# UNPINNED on purpose: not installed when the pins above were verified, and I
# don't know which versions support Python 3.9. pip picks the newest one that
# does. Once the real apps run, pin them here from `pip list`.
google-genai
python-dotenv
pillow
requests
runwayml

# Deliberately NOT here: pyaudio. It needs the PortAudio system library, which on
# a Mac means Homebrew, and Homebrew is winding down Intel-Mac support. If it is
# installed, core/mic.py uses it; otherwise it uses sounddevice.
